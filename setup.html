🔮 Quartz Setup Guide

Flash → Connect WiFi → Write down seed → Confirm → Mine. About 10 minutes.

1. Flash firmware → 2. Connect WiFi + node → 3. Write down seed → 4. Confirm (required!) → ⛏️ Mining
1Flash the Firmware

Get the files from the download page. You need one all-in-one image for your board:

  • ESP32-C3 (Super Mini, DevKitM): quartz-c3-merged-v077.bin
  • Classic ESP32 (DevKit, WROOM, M5Stack, LilyGO T3): quartz-esp32-merged-v077.bin
  • ESP32-S3 (Heltec V3): see the download page (build pending v077)

⚡ Easiest — one-shot flasher scripts (recommended)

Put the script next to the bin file, run it, plug the board in. It detects the port and flashes itself:

cd %USERPROFILE%\Downloads
curl -O https://quartzchain.net/downloads/flash_c3.py
curl -O https://quartzchain.net/downloads/quartz-c3-merged-v077.bin
python flash_c3.py

For classic ESP32 boards use flash_esp32.py + quartz-esp32-merged-v077.bin. On the C3 Super Mini, hold BOOT while plugging in if it won't connect — its auto-reset is finicky.

🔧 Manual esptool

Windows
macOS
Linux
  1. Install Python: python.org (check "Add to PATH")
  2. Open Command Prompt: pip install esptool
  3. Plug the board into USB. Open Device Manager → Ports → find your COM port (e.g. COM5)
  4. Flash the all-in-one image (C3 example):
python -m esptool --chip esp32c3 --port COM5 --baud 115200 write_flash 0x0 quartz-c3-merged-v077.bin

Classic ESP32: --chip esp32 ... 0x0 quartz-esp32-merged-v077.bin

pip install esptool
ls /dev/cu.*   # look for SLAB_USBtoUART or wchusbserial
python -m esptool --chip esp32c3 --port /dev/cu.SLAB_USBtoUART --baud 115200 write_flash 0x0 quartz-c3-merged-v077.bin
pip install esptool
ls /dev/ttyUSB*   # if permission denied: sudo usermod -aG dialout $USER
python -m esptool --chip esp32c3 --port /dev/ttyUSB0 --baud 115200 write_flash 0x0 quartz-c3-merged-v077.bin

Wait for Hash of data verified. The board resets itself and boots into setup mode.

⚠️ Flash doctrine — read this before your second flash:
  • Updating a board that already works? Flash the app-only image at 0x20000 — it preserves your wallet, seed, PIN, WiFi and node settings: 
    python -m esptool --chip esp32c3 --port COM5 --baud 115200 write_flash 0x20000 quartz-app-v077-c3.bin
  • The all-in-one image (0x0) is for new or bricked boards only. It wipes WiFi settings and the wallet — the image's padding overlaps the settings partition. A board flashed this way comes up with a fresh wallet and needs full setup again.
  • Bricked by the browser web flasher? (boot loop invalid header: 0xffffffff) — use the Python commands above instead. WebSerial can abort mid-write on some USB setups, leaving the flash half-erased. If the bootloader survived (the loop started right after an app-only update), the app-only command at 0x20000 revives it and keeps your wallet.
2Connect WiFi + Node (Portal)

On first boot (or after a full flash), the board broadcasts a setup hotspot:

  1. On your phone or computer, go to WiFi settings
  2. Connect to Quartz-XXXX (no password)
  3. A setup page pops up automatically — or browse to 192.168.4.1
  4. Enter:
    • WiFi name + password — your home network
    • Node — where the board gets mining work:
      • quartzchain.net — the reference node (default, works anywhere)
      • 192.168.x.x — a local node on your LAN (e.g. a Raspberry Pi) — faster work, no cloud dependency
  5. Click "Start Mining ⚡"
Node typo? The board will print Node unreachable, mining locally and get no new work. On v077 the fix is a small settings erase + re-run this portal step (see Troubleshooting below). v078 adds a node console command to fix it without reflashing.
WiFi is for mining only. Your seed phrase is never transmitted over WiFi — it's shown via serial console or BLE only. No captive-portal seed exposure.
3Write Down Your Seed Phrase

With a new wallet, the device generates a 12-word BIP39 seed phrase. Anyone with these words controls your wallet. The seed is shown on the serial console:

Windows
macOS
Linux
python -m serial.tools.miniterm COM5 115200
# (or PuTTY: Serial / COM5 / 115200 / flow control None)
# Press RESET on the board to see the full boot
# Quit miniterm: Ctrl+]
screen /dev/cu.SLAB_USBtoUART 115200
# Exit: Ctrl+A then Ctrl+\
screen /dev/ttyUSB0 115200
# Exit: Ctrl+A then k then y

The serial output shows your words and address:

╔════════════════════════════════════════════╗
║   🔮 QUARTZ WALLET — SEED PHRASE           ║
║   WRITE DOWN THESE 12 WORDS                ║
╚════════════════════════════════════════════╝

Address: QkYhsYVeBLb2rE16MPZBCwnDPDRTDahxt8
  1 capable    2 news       3 pyramid
  4 suspect    5 pumpkin    6 improve
  7 share      8 kiwi       9 praise
  10 eight     11 food      12 knee

Type 'confirm' + Enter after writing down your seed.
⚠️ Write them on paper. Not a screenshot. Not a text file.
  • Order matters — word 1 is word 1
  • Anyone with these 12 words can spend your coins
  • If the device dies and the paper is gone, the coins are gone — there is no other copy

Then type confirm and press Enter (or hold the BOOT button ~3 seconds, or confirm in the Android app).

⚠️ Mining does not start until you confirm. If the board seems up (WiFi connected, peers discovered) but you never see Mining started!, it is waiting for seed confirmation — forever, with no timeout. Type confirm + Enter in the serial console. This is the #1 "my board is half-alive" cause.
Lost the paper but still have the device? Type seed in the serial console to re-display the words (PIN-gated if a PIN is set — see step 4). Do it before anything happens to the device.
4Set a PIN (Recommended)

A PIN protects the seed command — without a PIN, anyone with USB access can re-display your 12 words. With a PIN, they get 10 wrong guesses before the wallet is wiped.

setpin 1234     ← set a 4-8 digit PIN

pin 1234        ← unlock (after each power cycle)
seed            ← re-display your 12 words
⚠️ 10 wrong PINs = wallet wiped. The counter persists across reboots — power-cycling does NOT reset it. If you forget your PIN, the only recovery is your 12-word seed phrase.
✓That's it. You're mining.

What a healthy boot looks like

I (6310) QZ.PUF: PUF enrolled! Fingerprint: 0a14acca...
I (6414) MAIN: Scratchpad allocated (16 KB)
I (6420) MAIN: BLE off (seed confirmed) — radio dedicated to WiFi
I (6438) MAIN: Mining started!
I (7251) QZ.WIFI: Got work: height=7514 target=13        ← within ~1s on a local node
I (807197) MAIN: Mining... 30 H/s, 56 total, nonce 55 [v077]
I (807587) QZ.MESH: Peer discovered: 08f9e0f652bc (caps=0x03 height=0)
  • Mining started! by ~7 seconds after reset — if it's not there, see the seed-confirm trap in step 3
  • Got work fast = node URL is right (local node: under a second; quartzchain.net: up to ~35s)
  • [v077] in mining lines = your firmware version
  • Peer discovered = another Quartz board in radio range (~200m) — you're meshing

Verify you're earning

Watch your address on the explorer, or import your 12 words in the web wallet. Blocks pay 42 QZ straight to your address.

Serial Commands

Commands depend on the board's state (characters echo back):

While mining

help                  Show available commands
address               Show your wallet address
seed                  Re-display your 12-word seed (PIN-gated)
pin / setpin / pinstatus    Unlock, set, or inspect PIN
send <addr> <amount>  Send QZ (requires unlock)
meshscan              List nearby WiFi networks + channels (mesh debugging)
meshch <1-13|0>       Lock/clear the mesh radio channel (0 = auto)

While waiting for seed confirmation (before first mining)

confirm               Confirm you wrote down the seed — starts mining
pin / setpin / pinstatus
wifi                  Wipe WiFi + node settings, reboot into portal
recover <12 words>    Restore a wallet from seed (v078)
Known gap (v078): wifi currently only works in the seed-confirmation state, not while mining. If you mistype your node URL on a running board, see Troubleshooting below.

FAQ

App-only vs all-in-one vs erase — what preserves what?

  • App-only (0x20000): keeps wallet, seed, PIN, WiFi, node. Use for every update on a working board.
  • All-in-one (0x0): bootloader + partitions + app in one file. New or bricked boards only — wipes WiFi + wallet.
  • erase_flash: full factory wipe. Only when you want a clean slate.

I can't type in the serial console — nothing appears

  • Check baud 115200 and flow control None (PuTTY default is XON/XOFF — change it)
  • Press RESET on the board — you should see boot messages
  • Type help + Enter — you should get a command list

I missed the seed display — can I see it again?

Yes: type seed (PIN-gated). If you haven't confirmed yet, power-cycle — the seed shows again on every boot until you type confirm.

What does the mesh do? Do I need it?

No setup needed — boards in radio range (~200m, same channel) find each other automatically. A board with no WiFi/node can mine through a connected peer, and blocks get relayed to the chain over whichever board has a link. Today it's a resilience layer; a future fork pays relayers 10% of block rewards.

My hashrate shows 0 H/s but it says "Got work via mesh"

Cosmetic estimator quirk with mesh-sourced work (v078 fix). Hashing is happening — check that nonce counter increments.

What boards are supported?

ESP32-C3 (Super Mini — the $3 starter, headless/serial), any classic ESP32 with 4MB+ flash (DevKit, WROOM/WROVER, M5Stack Core, LilyGO T3), ESP32-S3 (Heltec V3 — beta build). ESP32-S2 is not supported (no Bluetooth).

Do I need to keep it plugged in?

For mining: yes (power + WiFi), or run it off a USB battery — a C3 draws well under a watt. For wallet recovery: no — import the 12 words in the web wallet from any browser.

Are the 12 words compatible with other wallets?

Yes — standard BIP39 + BIP44 (m/44'/789'/0'/0'/0') with Ed25519 keys. Import the same words in the web wallet to get the same address.
