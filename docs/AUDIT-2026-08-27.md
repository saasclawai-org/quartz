## Findings not yet captured in MAINNET.md

### F1 — Public testnet runs out of the dev workspace (deploy hygiene)
`quartz-testnet.service` runs `testnet.py` with `WorkingDirectory=/home/nmoore/.openclaw/workspace/quartz/reference-node`. The public chain (quartzchain.net → nginx → :21100) executes directly from the repo any agent or edit touches. A stray `git checkout` or hot-fix edit mutates the production testnet with no deploy step, no rollback, no version pinning. The Pi one-tarball pattern already solves this — apply it to the VPS node too: deploy a pinned copy (e.g. `/srv/quartz/node/`), restart service from there.

### F2 — Simulator fleet is also the difficulty oracle
With 95% of blocks from `DEMO_MINERS`, difficulty-14 retarget data reflects simulator behavior, not hardware reality. P0-3 (simulator-off) is already flagged, but note the dependency explicitly: **difficulty parameters tuned while the simulator runs are unvalidated** — including the launch-difficulty choice (TODO.md §7 proposes difficulty 20 at launch; that number currently has no hardware-only evidence behind it at low-miner counts).

### F3 — Doc drift is starting
- `TODO.md` last updated 2026-08-10: says 176 tests (now 289), lists dev-fund multi-sig as resolved (good) but pre-dates the SIO2 ticker decision, quartzchain.net cutover, and v075 firmware.
- Wallet versioning changed schemes mid-stream (v00X → v0.2.x) — fine, but docs reference both without a mapping.
- ROADMAP.md "In Progress" items (Ed25519 flash, M5Stack orientation) are weeks stale.
Recommend a docs-freeze pass alongside P0-4: one `docs/STATE.md` that is regenerated (height, miners, test count, versions) rather than hand-edited.
