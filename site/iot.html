IoT Applications

The ESP32 is already the most deployed IoT platform on Earth. Quartz gives it a wallet and a reason to be in the field.

Let's be honest about what Quartz is and isn't.
Quartz is a cryptocurrency that runs on ESP32 hardware. The network moves block headers and transactions, not sensor telemetry. The ESP32 miners hash — they don't measure things by default.

But the ESP32 is a full microcontroller. It has GPIO, I2C, SPI, ADC, DAC, and (on some boards) LoRa. It sits in physical environments. The Quartz firmware already has on-chain messaging (256-byte data field) and GPIO relay control. These are the building blocks for practical IoT applications — not promises, just hardware capabilities plus a blockchain that runs on the same chip.

Use Case: On-Chain Sensor Logging

An ESP32 with a sensor logs readings to the blockchain. The chain IS the database.

🌡️

Cold Chain Monitoring

Works today (on-chain messaging)

An ESP32 with a DS18B20 temperature sensor ($2) sits inside a refrigerated truck or shipping container. Every 5 minutes, it takes a reading and submits a Quartz transaction with a 256-byte data payload containing the temperature, timestamp, and device ID.

The blockchain becomes an immutable audit trail. No server to hack, no database to alter, no cloud subscription. Anyone with the device's address can verify the temperature history on the block explorer.

ESP32 + DS18B20 │ reads temperature every 5 min │ packs: {temp: 3.2°C, ts: 1723976400, dev: "cold-001"} │ submits Quartz tx with 256-byte data field ▼ Quartz blockchain (immutable) │ visible on block explorer │ queryable via /api/v1/address/<addr> ▼ Auditor checks: "Was this truck ever above 4°C?" → reads on-chain messages from device address → sees complete temperature history, timestamped by blocks

Parts needed: ESP32 ($5) + DS18B20 sensor ($2) + solar panel ($3) = $10 total. No subscription, no cloud, no API key.

Bandwidth: One 256-byte transaction every 5 minutes = ~7KB/day. Fits easily over LoRa mesh via a bridge.

Agricultural Sensor Array

Requires sensor firmware (not yet written)

A cluster of ESP32s with soil moisture, temperature, and humidity sensors spread across a field. Each logs readings on-chain. The data is visible to the farmer, the crop insurer, and the supply chain — all from the same immutable record.

The ESP32s mine Quartz between readings, earning QZ to offset their own cost. A Helium hotspot bridge on the farm provides the LoRa → internet link. No WiFi needed in the field.

Field sensors (ESP32 + soil probe) │── LoRa (2-15km) ──→ Bridge (Helium hotspot on barn) │ │── WiFi ──→ Quartz gateway │ ▼ │ Blockchain records: │ block 42,051: {soil: 31%, temp: 22°C, dev: "field-A-01"} │ block 42,052: {soil: 28%, temp: 23°C, dev: "field-A-02"} │ └── Also mining Quartz between readings

Parts needed: ESP32 + soil moisture sensor per node (~$8 each). One Helium hotspot as bridge. Solar panels for off-grid nodes.

What's ready: LoRa mesh, on-chain messaging, bridge relay. What's not: Sensor reading firmware (I2C driver + tx formatting). Straightforward — days of work, not weeks.

Solar Charging Station

Works today (GPIO relay + QR payment)

An ESP32 controls a relay connected to a USB port. A solar panel charges a battery. When someone sends QZ to the device's address, the relay closes for 30 minutes — phone charging.

The QR code on the device encodes a payment request. User scans with the Quartz wallet, sends QZ, device activates. No payment processor, no monthly fee, no internet required if on LoRa mesh.

User scans QR code on device │ QR contains: quartz:<device-address>?amount=5 ▼ Quartz wallet sends 5 QZ to device address ▼ Device sees transaction on-chain (via WiFi or LoRa mesh) │ closes GPIO relay for 30 minutes ▼ USB port powered → user charges phone Meanwhile: device mines Quartz between customers → earns QZ from mining + QZ from charging fees → self-sustaining

Parts needed: ESP32 ($5) + relay module ($2) + solar panel + battery + USB port. Total ~$20.

Deployment: Hiking trails, rural areas, festivals. Anywhere with sun and a phone that needs charging.

🚰

Pay-Per-Water Irrigation Valve

Requires solenoid driver (trivial GPIO)

An ESP32 controls a solenoid valve on an irrigation line. A farmer pays QZ to open the valve for a set duration. The device logs each activation on-chain — creating a verifiable record of water usage.

For tenant farmers or shared irrigation systems, this solves the "who paid for water" problem without a middleman. The blockchain is the receipt.

Parts needed: ESP32 + relay + 12V solenoid valve. ~$15. What's ready: Payment trigger, GPIO control, on-chain logging. What's not: Valve-specific wiring (an afternoon).

What Quartz Is NOT

Honest boundaries. We'd rather under-promise.

❌

Not a LoRaWAN replacement

Quartz doesn't relay LoRaWAN packets or talk to LoRaWAN sensors. The LoRa mesh uses its own packet format for Quartz blockchain data. If you have existing LoRaWAN sensors, they won't automatically work with Quartz.

❌

Not a sensor data marketplace

Helium tried to build a marketplace where sensor data buyers pay for telemetry. That model failed. Quartz doesn't attempt it. Sensor data goes on-chain as a transaction, but there's no built-in marketplace to sell it. The value comes from mining, not data sales.

❌

Not real-time IoT

Block time is ~120 seconds. LoRa bandwidth is ~250 bytes per packet. If you need millisecond latency or streaming telemetry, use WiFi or cellular. Quartz is for low-frequency, high-value data where immutability matters more than speed.

❌

Not enterprise IoT

No device management dashboard, no fleet OTA updates, no LDAP integration. Quartz is a cryptocurrency that happens to run on IoT hardware. If you need enterprise IoT features, use AWS IoT or Azure IoT Hub.

Quartz vs Helium for IoT

Different model, same hardware.

Helium (IoT Network)

  • Hotspots relay LoRaWAN sensor data
  • Revenue from data credits (sensor packets)
  • Requires sensor deployments to generate demand
  • Hotspot owners earn based on network usage
  • Centralized company (Nova Labs) controls roadmap
  • Token value tied to sensor data volume
  • Result: not enough sensor data, tokens crashed

Quartz (Cryptocurrency on IoT)

  • ESP32s mine a cryptocurrency (PUF-bound)
  • Revenue from mining rewards (block emission)
  • Mining is the demand — doesn't need sensor buyers
  • Miners earn from securing the network
  • Open source, MIT licensed, no company
  • Token value tied to network security + adoption
  • Sensor logging is a free feature, not the business model
The key difference: Helium needed sensor data buyers to exist before the network had value. Quartz needs miners to exist — and mining works from day one. IoT applications (sensor logging, pay-per-use hardware) layer on top of a network that's already economically viable, rather than being the reason the network exists.
