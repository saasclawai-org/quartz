🧠 Village LLM

A Raspberry Pi sells local-AI completions for QZ — the "solar-powered village LLM." No escrow, no accounts: you pay the node's Quartz address (an ordinary on-chain transaction), it verifies your payment against the chain itself, and answers with a completion plus an Ed25519-signed receipt anyone can verify. Txids are single-use — replay is impossible.

What just happened

    
1 · POST /request → the node creates a job and quotes its price.

    2 · You pay its Quartz address — a plain on-chain transaction, from any wallet.

    3 · POST /claim {job_id, txid} → the node checks the chain's own API: right address? enough?
    confirmed? txid unused?

    4 · It runs the local model and returns the completion + a signed receipt
    (prompt_sha256, completion_sha256, model, price, txid + Ed25519 signature).

    5 · POST /verify proves the signature — no trust in this page required.

    

      Node offline? Owner setup (2 steps)
      
This demo talks to the LLM node running on a Pi at
      pi.quartzchain.net (behind Cloudflare, path /llm/ → port 8788).
      To bring it up:

      
1 · On the Pi — install the node bundle with the LLM flavor:

      
curl -LO https://quartzchain.net/downloads/quartz-pi-node.tar.gz
tar xzf quartz-pi-node.tar.gz && cd quartz-pi-node
sudo INSTALL_LLM=ollama bash install.sh   # real model
# or: sudo INSTALL_LLM=mock bash install.sh  (demo backend, zero deps)

      
2 · Expose port 8788 through Cloudflare — dashboard → Rules → Origin Rules:
      match Hostname eq pi.quartzchain.net AND URI Path starts with /llm/ →
      Destination Port 8788. (Or on the Pi's nginx:
      location /llm/ { proxy_pass http://127.0.0.1:8788/; })
